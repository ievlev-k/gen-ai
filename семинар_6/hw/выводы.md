## 1. Валидатор схемы

**Сигнатура:**

```python
VALID_TOOLS = {"get_fx_rate", "get_key_rate", "get_inflation", "calculate"}

def validate_plan(plan: Plan) -> list[str]:
    errors: list[str] = []
    for sq in plan.subquestions:
        for tool in sq.expected_tools:
            if tool not in VALID_TOOLS:
                errors.append(f"SubQuestion #{sq.id}: выдуманный инструмент «{tool}»")
        for dep_id in sq.depends_on:
            if dep_id not in {s.id for s in plan.subquestions}:
                errors.append(f"SubQuestion #{sq.id}: зависит от несуществующего #{dep_id}")
    return errors
```

Встроен в `run_pwc()` сразу после `planner()`. При ошибках Планировщик получает фидбек и строит план заново.

Примеры пойманных ошибок:
- `get_cumulative_inflation` - инструмента нет, разрешены только get_fx_rate, get_key_rate, get_inflation, calculate
- `depends_on=[99]` - подвопроса #99 в плане нет

## 3. Замер угодливости Критика

5 заведомо битых наборов ответов, по 10 прогонов каждый, T=0.0 и T=0.7.

| Кейс | T=0.0 | T=0.7 |
| -------- | ----------------- | -------- |
| Арифметика без calculate | 0/10 | 1/10 |
| Выдуманное число | 1/10 | 0/10 |
| Несогласованные данные | 1/10 | 4/10 |
| Ошибка в ответе | 0/10 | 0/10 |
| Не вся часть вопроса | 1/10 | 2/10 |
| **Итого** | **3/50** | **7/50** |

При T=0.7 ложных OK больше в 2 раза. Гипотеза «шум лечит слепое согласие» не подтвердилась. T=0.0 работает строже, особенно на несогласованных данных (1/10 против 4/10).

## 4. Eval 6 вопросов × 3 конфигурации × N=5

| ID | Вопрос | Одиночный | PWC | PWC+вал |
| -------- | ----------------- | -------- | -------- | -------- |
| Q1 | Во сколько раз USD подорожал с 01.01.2022 | 5/5 | 3/5 | 3/5 |
| Q2 | Реальная ставка по последнему доступному месяцу | 5/5 | 2/5 | 1/5 |
| Q3 | Накопленная инфляция от 51 месяца | 0/5 | 0/5 | 0/5 |
| Q4 | Реальная ставка по годам 2022-2025 | 5/5 | 5/5 | 3/5 |
| Q5 | Курсы USD, EUR, CNY + сравнение | 5/5 | 3/5 | 5/5 |
| Q6 | Рост ставки с начала 2022 | 5/5 | 5/5 | 5/5 |

- Q3 - все три конфигурации 0/5. 51 вызов get_inflation не влезает в max_iter исполнителя.
- Q5 - единственный вопрос, показавший поправку валидатора: PWC 3/5, PWC+валидатор 5/5. Планировщик иногда добавляет выдуманный инструмент, валидатор ловит и заставляет перепланировать.
- На Q6 все три варианта дают 5/5 - простой вопрос.

## 5. Вывод

PWC оправдан когда:
- Вопрос разбивается на 2-4 подвопроса с зависимостями (сначала данные, потом расчёт).
- Нужно проверить, что числа согласованы между шагами.

PWC не нужен когда:
- Вопрос решается за 2-3 вызова - одиночный агент быстрее (Q2, Q6).
- Нужно много повторяющихся вызовов (Q3, 51 месяц) - Исполнитель упрётся в max_iter.

Итого: одиночный агент лучше на 4 из 6 вопросов. PWC+валидатор нужен, когда Планировщик склонен выдумывать инструменты - валидатор это ловит. Без этого случая PWC только добавляет накладные расходы: минимум 3 LLM-запроса vs 1 у одиночного.
